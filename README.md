# Информационное сопровождение интерактивной экспозиции выставочного центра

Учебная практика, РТУ МИРЭА, группа ИКБО-30-24, Ирхин А. В.
Тема: «Работа выставочного центра с интерактивными экспозициями».

Комплекс позволяет куратору публиковать сведения об экспонатах в одном месте, а интерактивным стендам —
получать обновления без пересборки и установки программ, а также собирать статистику обращений посетителей.

## Структура репозитория

| Каталог | Содержимое |
|---|---|
| `docs/bpmn/` | BPMN-модель текущего (AS-IS) процесса: `process_as_is.bpmn` и изображения |
| `docs/data-model/` | Логическая модель данных в нотации Мартина (IE) |
| `docs/algorithms/` | Блок-схемы алгоритмов по ГОСТ 19.701-90 |
| `docs/uml/` | UML-диаграммы модуля `exhibition-core` (исходники PlantUML и изображения) |
| `algorithms/` | Процедурная реализация алгоритмов на Java (Maven, JUnit 5) |
| `algorithms/data/` | Общие тестовые данные в формате CSV |
| `exhibition-core/` | Объектно-ориентированная реализация тех же алгоритмов — ядро серверной части (Java 17, JUnit 5) |
| `pom.xml` | Сборка обоих Java-модулей одной командой |

Подключение базы данных PostgreSQL и веб-клиент стенда (JavaScript, Three.js) будут добавлены на следующих этапах.

## Алгоритмы

| № | Алгоритм | Код | Сложность |
|---|---|---|---|
| 1 | Синхронизация контента стенда: что загрузить, обновить и удалить | `ContentSync` | O(n + m + k log k) |
| 2 | Регистрация событий: проверка размещения и публикации на момент события | `EventRegistration` | O(p log p + v log v + k log h) |
| 3 | Агрегация статистики, рейтинг и невостребованные экспонаты | `StatisticsAggregation` | O(k + q log q + x) |

n — экспонатов в плане стенда, m — в манифесте стенда; k — в алгоритме 1 суммарная длина списков
изменений, в алгоритмах 2 и 3 число событий; p — размещений, v — версий публикации, h — наибольшая
длина истории одной пары «стенд — экспонат» или одного экспоната; q — экспонатов с обращениями,
x — экспонатов экспозиции. Периоды размещений и публикаций (`Periods`) действуют в полуинтервале
[начало, окончание).

## Объектно-ориентированная реализация (`exhibition-core`)

| Пакет | Назначение |
|---|---|
| `domain` | Предметная область: выставка, экспонат, стенд, размещение, версия публикации, период |
| `history` | История периодов с двоичным поиском записи, действовавшей в заданный момент |
| `catalog` | Каталог экспозиции: что было размещено и опубликовано в момент t |
| `data` | Источник данных (интерфейс `ExhibitionRepository`, чтение CSV) и данные от стендов |
| `sync` | Алгоритм 1 — `ContentSyncService` |
| `registration` | Алгоритм 2 — `EventRegistrationService` и правила проверки событий (`EventRule`) |
| `stats` | Алгоритм 3 — `StatisticsService` |
| `app` | Демонстрационная программа `Main` |

Каждая проверка события — отдельный класс, реализующий интерфейс `EventRule`; служба регистрации применяет
правила по порядку. Правило `ExhibitionOpenRule` (событие учитывается, только если выставка открыта для
посетителей) — пример нового требования: оно подключается одной строкой в методе
`EventRegistrationService.standard` и не затрагивает другие правила.
UML-диаграммы модуля — в `docs/uml`; общая диаграмма всех классов — `docs/uml/class_overview.png`.
На общих тестовых данных обе реализации дают одинаковый результат (тест `DemoDataTest`).

| Файл | Содержимое |

## Как проверить

Требуется JDK 17 или новее. Оба модуля собираются Maven.

**IntelliJ IDEA**

1. File → Open → выбрать файл `pom.xml` в корне репозитория → Open as Project
   (откроются оба модуля: `algorithms` и `exhibition-core`).
2. Тесты: правой кнопкой по каталогу `src/test/java` нужного модуля → Run 'All Tests'.
3. Демонстрация: открыть `Main.java` модуля (`ru.mirea.exhibition.procedural.Main` или
   `ru.mirea.exhibition.core.app.Main`) → зелёная стрелка у метода `main` → Run.
   Программы читают CSV из `algorithms/data` и выводят результаты трёх алгоритмов.

**Командная строка**

```
mvn test
```

Необязательные аргументы `Main`: каталог данных, id стенда, текущее время (ISO-8601), например
`data ST-01 2026-10-27T18:00:00`.

Если в консоли вместо русских букв видны «????», добавьте в Run Configuration → VM options:
`-Dstdout.encoding=UTF-8`.
